# 기록·삭제·회원탈퇴 공통 개발 기준

기준일: 2026-11-01 Asia/Seoul. 대상: ONARIA / NAREUM(buddhist) / MAEON(catholic) / SORUA. 이전 philosophy 시안은 대상이 아니다.

## 공통 사용자 계약

| 작업 | 삭제 범위 | 유지하는 것 | 완료 기준 |
|---|---|---|---|
| 개별 기록 삭제 | 사용자가 고른 현재 계정의 해당 기록 | 다른 기록·다른 회원·회원 계정 | 저장소 성공 응답 뒤 목록 갱신 |
| 이 기기의 내 기록 전체 삭제 | 현재 회원 또는 비회원의 기기 카드·실천·여정·초안·관련 기록 | 서버 기록·회원 계정·타 계정·미확인 이전 기록 | 진행 중 저장 종료 대기, 이전 저장 세대 차단, 정확한 범위 제거 후 재조회 검증 |
| 서버의 내 기록 전체 삭제 | 명시적으로 서버에 저장한 현재 회원 기록 | 회원 계정·다른 회원·기기 기록 | 서버 인증·CSRF·트랜잭션·삭제 원장/백업 파기 반영 성공 |
| 회원탈퇴 | 이 앱 서버 계정과 연결 개인정보·로그인·세션·해당 회원 기기 정리 | 다른 앱 계정·다른 회원·소셜 제공자 자체 계정 | 새 본인 확인, Apple 연결 시 토큰 해제, 서버 삭제 확인; 기기 정리 실패는 별도 표시 |
| 저장·AI 동의 철회 | 이후 처리 중지와 각 기능이 명시한 기존 기록 정리 | 삭제 대상으로 표시하지 않은 기록 | 서버 반영 여부 확인; 미확인 상태에서 새 저장 금지 |

- 로그아웃, 앱 삭제, 기록 삭제, 회원탈퇴를 같은 의미로 사용하지 않는다.
- 취소·연속 누름·오래된 화면 콜백·다른 계정으로 변경·백그라운드 이동·통신 단절·부분 실패를 검사한다.
- 대화 원문을 전체 자동 저장하지 않는다. 임시 문장 자동 복구는 사용자의 별도 선택을 유지한다.
- 계정·서버·DB·API·OAuth·키·저장 namespace·콘텐츠는 앱마다 독립적이다. 공통 문구는 공유해도 회원 데이터를 합치지 않는다.
- 기기 기록은 웹에서는 현재 브라우저 저장소를 뜻한다. 다른 기기·OS 백업·외부 공유 사본을 지웠다고 표시하지 않는다.
- Android는 네 앱 모두 allowBackup=false. 이 설정은 이전 OS 백업을 소급 삭제하거나 모든 제조사 전송을 보장하지 않는다. iOS OS 백업은 별도 범위이며 삭제 안내에 표시한다.
- 회원 수집과 서버 저장의 활성화는 인증·삭제·동의·보유기간·공지와 실제 환경 검증이 일치할 때만 가능하다. 모의 코드와 로컬 테스트를 운영 완료로 표시하지 않는다.

## Apple / Google 근거

확인일 2026-11-01. 아래는 공통 기술 기준이며 심사 통과 보장이 아니다.

1. Apple 5.1.1(v): 계정 생성이 있으면 앱 안에서 계정 삭제를 시작할 수 있어야 하며 계정과 연결 데이터를 삭제한다. 일반 앱의 앱 내 삭제를 필수 이메일·전화 문의로 대체하지 않는다. Apple 로그인 토큰 해제를 유지한다.
   https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion/
2. Google: 계정 생성 앱은 앱 안과 외부 웹에서 삭제 요청 경로를 제공한다. 외부 경로는 앱 재설치가 없어야 하며 앱명·방법·보관 범위를 표시한다. 웹 이메일 요청 경로는 수동 접수이며 자동 완료가 아니다.
   https://support.google.com/googleplay/android-developer/answer/13327111?hl=en
3. Google Data safety는 SDK를 포함하며 잠깐의 기기 외 전송도 양식의 일시 처리 기준으로 검토한다. 기기 내 처리만이라는 이유로 로그인·외부 AI·OS 서비스·SDK 전송을 누락하지 않는다.
   https://support.google.com/googleplay/android-developer/answer/10787469?hl=en
4. Apple App Privacy는 수집 정의와 외부 SDK를 별도로 확인한다. Google과 Apple의 수집 정의가 달라 같은 체크값을 복사하지 않는다. 현재 배포 버전과 새 후보 빌드의 기능 차이를 구분한다.
   https://developer.apple.com/app-store/app-privacy-details/
   https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/

## 등록 전 증거

- 앱의 삭제·동의·마이크/음성 인식·알림 실제 동작, SDK 최종 아카이브 개인정보 매니페스트, 지원·개인정보·삭제 URL의 HTTPS 응답을 확인한다.
- 보유기간은 데이터 항목별 기산점·기간·최대 실제 파기 시점·백업·외부 처리자 삭제를 기록한다. 법적 근거 없는 보존 예외를 새로 만들지 않는다.
- UI 공통화와 보관기간 동일화는 다른 작업이다. 서로 다른 운영 보유기간을 문구만 통일하거나 운영 DB 파기를 자동 실행하지 않는다. 기존 정책과 실제 정리 작업을 대사한 뒤 수정한다.
- 심사 노트에는 실제 로그인 수단, 선택 동의, 계정 삭제 진입점, 외부 요청 URL, 서버 모드, 검토 계정 제공 방식만 적는다. 비밀값과 실제 사용자 기록은 넣지 않는다.
- 로컬 CODE/TEST, 빌드, 실서버 REAL, 실기기 DEVICE, 스토어 양식/심사 USER 증거를 따로 기록한다.
- 공식 심사 제출·등록본 교체·운영 배포와 테스트용 코드 검증을 구분한다. 새 코드만으로 기존 배포 앱/웹이 갱신된 것으로 표시하지 않는다.

## 저장소별 점검 명령

`python3 scripts/verify-data-rights.py --source-only`는 소스 공통 계약만 검사한다.
`python3 scripts/verify-data-rights.py`는 실제 공개 후보·실기기·양식 검증 증거까지 확인하며, 미확인 시 종료 코드 2와 BLOCKED를 반환한다. 이 검사는 별도 배포·기기 설치·양식 수정·심사 제출을 실행하지 않는다.
