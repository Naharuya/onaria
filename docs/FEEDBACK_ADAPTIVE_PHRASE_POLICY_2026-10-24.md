## 사용자 결정

사용자 설명: “선택적 답변 평가를 서버 메모리에 저장하는 이유는 반복적으로 답변하는 문구에 대해 능동적으로 추가 저장하는 기능이 있어서 그런거야. 그 부분을 명시해서 .md 파일에 저장해 두고 앞으로의 정책도 그 방향으로 유지해”.

선택적 답변 평가의 목적은 **반복적으로 사용되는 답변 문구를 개선하고, 필요한 문구를 능동적으로 추가 저장하는 기능을 지원하는 것**으로 유지한다. 향후 정책·설계·고지는 이 목적을 명시하고 실제 데이터 흐름과 함께 관리한다. 평가 집계 자체와 문구 후보 저장·검토·활성 응답 반영은 각각 구분해 기록한다.

## 정책 유지와 구현 기준

1. 정책 목적에는 반복 답변 문구 개선과 능동적인 추가 저장 기능 지원을 명시한다. 실제 적용한 항목·저장 위치·목적·읽는 경로·보유/삭제·활성 반영 상태를 함께 갱신한다.
2. 현재 선택적 평가와 향후 문구 후보 저장을 혼동하지 않는다. 평가 집계가 이미 자동 학습·영구 저장·실시간 응답 반영을 수행한다고 주장하지 않는다.
3. 이 결정은 대화 원문·계정·종교·건강 등 민감내용의 추가 수집·무제한 보관·외부 학습 전송을 포괄 승인한 것이 아니다. 추가 데이터가 필요하면 실제 최소 항목·전송 전 안내·동의·보유/파기와 테스트를 먼저 구체화한다.
4. 추가 저장할 문구의 출처·중복·안전·종교 인용 무결성·수정 이력을 확인한다. 위기 경로는 고정 로컬 응답과 모델 호출0 조건을 유지한다. 승인된 경전/교리 근거 없이 문구를 만들어 활성화하지 않는다.
5. 보유기간은 실제 구현·운영 근거 없이 일수로 확정하지 않는다. 현재 피드백 메모리에 일반 로그14일/원장62일 파기 작업이 적용된다고 쓰지 않는다. 접속 로그는 별도 처리 경로다.
6. 공개 개인정보처리방침·스토어 답변은 실제 데이터 흐름과 일치시켜 별도 검토한다. 이번 사용자 요청은 이 Markdown 정책 기록이며 공개 정책 게시·운영 변경·새 수집 경로 구현은 실행하지 않았다.

## 다음 확인과 완료 기준

- 기존 문구 추가 저장 기능이 위치한 실제 모듈/저장소/운영 경로를 확인하고, 평가→반복 감지→후보 저장→검증→활성 응답 읽기 연결을 재현한다. 확인 전에는 구현 완료나 미구현 전체로 단정하지 않는다.
- 기존 구현이 확인되면 그 데이터 계약과 삭제 경로를 재사용한다. 없으면 현재 전송 범위를 유지한 채 설계·최소 수집·검증 조건을 먼저 정한다.
- 테스트는 평가 선택/취소·중복, 후보 중복·민감내용 혼입, 출처/종교 경계, 활성 반영·되돌리기, 보유/삭제 및 Safety 회귀를 실제 구현 범위에 맞춰 연결한다.
- CODE/TEST/REAL/USER를 분리한다. 이번 기존 feedback backend 회귀는2PASS이며, 문구 추가 저장 기능의 검증을 대신하지 않는다.
