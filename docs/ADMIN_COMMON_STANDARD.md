# 네 앱 공통 관리자 기준

2026-11-01 사용자 요청. 대상: ONARIA / NAREUM(buddhist) / MAEON(catholic) / SORUA. 과거 philosophy 시안은 대상이 아니다.

## 구조

각 저장소가 동일한 backend/src/common_admin.js와 공통 관리 UI 모듈을 소유한다. 실행 시 다른 저장소를 import하거나 계정·DB·OAuth·키·세션을 공유하지 않는다.
기존 관리자·콘텐츠 API를 유지하며 공통 관리 작업 공간을 추가한다. 기존 종교별 출처/사용권/전문검수/게시 제한을 해제하지 않는다.
서버 프레임워크·신원 확인 방식은 각 앱의 안전한 기존 어댑터로 연결한다. 메뉴를 숨기는 것만으로 권한을 제한하지 않는다.

| 역할 | 공통 관리 권한 |
| --- | --- |
| owner | 관리자 권한 설정과 모든 공통 작업 |
| admin | 회원 집계, 요청 처리·독립 승인, 문의, 감사, 백업 증거 조회, 콘텐츠 등록·독립 검수 |
| editor | 콘텐츠 검수 대상 등록·조회 |
| reviewer | 콘텐츠 조회·독립 검수 |
| support | 삭제·철회 접수/상태 관리, 문의 배정/처리 |
| operator | 감사·백업/복구 증거 조회 |
| viewer | 공통 기준 조회 |

모든 역할은 본인 작성 콘텐츠를 스스로 검수할 수 없다. 삭제 요청 작성자는 자기 요청의 처리 승인을 할 수 없다.
권한 변경/중지는 다음 요청부터 반영한다. MAEON은 관리자 권한 변경 시 기존 관리자 세션을 폐기하므로 다시 재인증한다.
알 수 없는 역할/권한은 거부한다. 문의 답변 전송·메일 발송 권한을 이 작업에서 추가하지 않았다.

## 로그인과 계정 관리

ONARIA/NAREUM/SORUA: 기존 HttpOnly·SameSite=Strict 세션, 운영 HTTPS, 동일 출처, CSRF, 로그인 제한을 유지한다. 개별 관리자 ID+비밀번호(scrypt 해시)와 소유자 인증키 경로가 있다.
소유자만 관리자를 생성·역할 변경·중지한다. 자신의 권한 변경은 거부한다. 인증키/비밀번호는 브라우저 영구 저장소에 넣지 않는다.
MAEON: 기존 검증된 provider 회원 신원→새 재인증 증명→별도 단기 관리자 세션을 유지한다. 기존 회원 내부 ID에 역할을 부여하며 별도 비밀번호 회원을 생성하지 않는다.
첫 MAEON owner 지정은 기존 신뢰된 control-plane grantRole로 수행한다. 일반 회원이 HTTP로 자기 권한을 올릴 수 없다.
실제 관리자 가입·자격 증명 발급·운영 활성화는 수행하지 않았다.

## 회원·삭제 요청

공통 회원 화면은 실제 저장소의 회원 수만 제공하며 이름/전화/대화/소셜 신원 원문은 노출하지 않는다.
삭제·철회는 account_deletion / server_records / consent_withdrawal을 구분한다.
상태: received → identity_pending → approved → processing → completed. 종료 전 반려는 rejected.
identity_pending은 기존 본인확인 경로를 안내하는 상태다. 운영자가 버튼을 눌렀다는 이유로 본인확인을 완료했다고 기록하지 않는다.
승인은 담당자가 처리할 수 있도록 배정하는 승인이고, 본인확인이나 실제 삭제를 대신하지 않는다.
완료는 서버가 주입한 읽기 전용 verifyDeletion 어댑터의 증거가 현재 앱/요청 참조/범위와 일치하고 identityVerified, sessionsRevoked, backupProtected, providerRevoked, completed가 모두 true일 때만 허용한다.
브라우저 입력으로 이 사실들을 지정할 수 없다. 어댑터가 없으면 503 DELETION_VERIFIER_UNAVAILABLE, 증거 불일치는 409 DELETION_UNCONFIRMED로 processing을 유지한다.
기본 런타임에는 새 완료 확인기를 임의 연결하지 않았다. 기존 앱 내 본인확인·Apple 연결 해제·삭제/복구 차단 경로가 실제 집행 경로다. 새 관리자 우회 삭제 API는 없다.
현재 구조의 관리자 요청 큐는 내부 접수 참조번호 관리다. 이메일을 읽거나 외부 문의를 자동 수집하지 않는다. 개인 기기의 기록을 원격 삭제했다고 표시하지 않는다.

## 문의

기존 보호된 문의 경로에서 원문을 확인하고 공통 큐에는 내부 참조번호와 general/privacy/technical/content 분류만 기록한다.
received → assigned → resolved, resolved → received 재개를 제공한다. 담당자 내부 ID와 버전을 검사한다.
문의 원문·연락처·개인 대화·인증정보를 공통 큐나 감사 상세에 넣지 않는다. 기존 NAREUM 문의 API/승인된 답변 구조는 보존한다.
resolved는 내부 처리 상태이며 이메일 발송 완료를 뜻하지 않는다.

## 감사와 저장

업무 변경과 공통 감사 이벤트를 한 DB 트랜잭션에서 저장한다. 실패 시 둘 다 되돌린다.
감사에는 담당자/역할/작업/임의 내부 행 ID/시각/연결 해시만 넣고 요청 원문은 제외한다. 권한/상태 거부도 가능한 경우 별도 최소 이벤트를 기록한다.
연결 해시 검증 실패 시 추가 변경을 차단한다. 이 연결 해시는 DB 전체를 다시 쓸 수 있는 공격자에 대한 외부 불변 보관소를 대신하지 않는다.
세 Express 앱은 독립 SQLite operations 저장소를 사용한다. ONARIA/SORUA 개별 계정·감사 DB는 해당 회원 DB 옆 private admin-control 디렉터리에 생성하도록 연결했다.
MAEON은 기존 서비스 DB의 암호화 seal/unseal과 트랜잭션/worker fencing을 사용한다. 메모리 기본 모드는 메모리이며 영속 런타임과 구분한다.
MAEON 기존 admin/reviewer 역할 행은 트랜잭션으로 보존하면서 7개 역할 CHECK 제약으로 확장하는 마이그레이션 코드를 추가했다. 실제 운영 DB에는 실행하지 않았다.
기존 서비스 백업에 공통 운영 메타데이터가 자동 포함된다고 주장하지 않는다. 별도 operations DB 및 MAEON 공통 상태의 보관·복구·감사 보유 정책은 운영 연결 전에 함께 확정/검증한다.

## 백업·복구 확인

공통 API는 backup / restore / deletionProtection을 각각 PASS / FAIL / UNVERIFIED로 구분한다.
내부 inspectBackup 어댑터가 제공한 시각/환경(synthetic/candidate/production)만 표시하며 경로·키·백업 원문은 노출하지 않는다.
어댑터가 없으면 configured=false와 모든 UNVERIFIED다. 테스트 성공을 운영 복구 검증으로 바꾸지 않는다.
화면은 조회 전용이다. 실제 데이터 복구/덮어쓰기/운영 DB 초기화를 실행하지 않는다.
현재 각 서버의 실제 백업 증거 어댑터는 기본 미연결이다. 출시/운영 적용 시 해당 앱의 보관 위치·백업 정책·삭제 후 복구 차단을 검증하고 어댑터를 연결해야 한다.

## 콘텐츠 검수 프로필

| 공통 항목 | 전 앱 |
| --- | --- |
| source | 원문·출전 확인 |
| rights | 사용권 근거 |
| translation | 원문·번역·자체 해설 구분 |
| safety | 안전·차별·강요 검토 |

| 앱 | 추가 항목 |
| --- | --- |
| ONARIA | 성경 장절/문맥, 번역본/판본, 교단별 해석 구분 |
| NAREUM | 경전 장절, 종파/전통 구분, 원문과 번역 초안 분리 |
| MAEON | 가톨릭 정경/출전, 인준·번역본 상태 고지, 허용 교리 범위 |
| SORUA | 저자/작품/장절, 실제 인용 대조, 복수 철학 관점 |

검수 대상은 콘텐츠 참조와 버전으로 고정한다. 필수 7항목 모두 확인하고 별도 검수자/근거 문서 참조를 기록해야 pending → reviewed로 바뀐다.
reviewed는 공통 검수 기록이며 자동 게시나 종교기관 인준이 아니다. 기존 콘텐츠 게시 파이프라인/출처·사용권·검수 Gate와 함께 적용한다.
공통 큐를 통과했다고 기존 게시 제한을 생략하지 않는다. 기존 콘텐츠가 이 큐에 일괄 이관되거나 자동 재승인되지는 않는다.
MAEON의 교리 자료 비활성 및 출시 후 전문 검수 방침, NAREUM의 미승인 자료 제외, SORUA의 검증 인용 기준을 유지한다.

## 사용자 화면과 운영 상태

세 Express 앱: /admin/common, API /v1/admin/common/*.
MAEON: 기존 admin/console.mjs 내 공통 관리 섹션, API /api/v1/admin/common/*. 기존 adminEnabled와 별도 재인증 Gate가 먼저 적용된다. 진단 서버와 계정 운영 런타임의 관리자 비활성 기본값을 바꾸지 않는다.
모바일/데스크톱, 키보드용 폼/레이블, 확인창, 요청 중 버튼 잠금, 화면 전환 시 이전 폼 제거, 숨김 시 요청 취소·내용 제거를 적용한다.
CODE / TEST / 운영 서버 / 실기기 / 스토어 검증을 구분한다. 이 문서는 스토어 승인이나 운영 기능 활성화를 보증하지 않는다.
운영 배포·DB 마이그레이션·실기기 설치·스토어 변경·commit/push는 별도 사용자 지시 범위다.
