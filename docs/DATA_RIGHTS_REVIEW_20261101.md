## 확인한 문제와 수정

- 세 앱에 종류별 삭제는 있었지만 모든 계정별 로컬 기록을 한 번에 지우는 공통 동작이 없었다. RecordPreferences가 기기 쓰기를 직렬화하고, 이미 OS로 전달된 쓰기를 기다리며, 삭제 전 세대의 새 쓰기를 거절한다. 전체 삭제는 정확한 현재 namespace만 제거하고 재조회한다. 계정 전환 중에는 중단한다. 기존 미확인 원본·다른 계정·세션 자격 증명은 보존한다.
- 불교의 개인정보/삭제 링크가 .invalid였다. 독립 도메인 buddhist.ai.kr로 수정했다. 기존 운영자 지원 inbox(vjsjv7003@gmail.com)를 NAREUM 공통 삭제 접수 연락처로 코드에 설정했다. 이메일을 발송하거나 새 계정/키를 만들지 않았다. 운영자/법정 사업자 표시와 담당자 운영 확인은 출시 전 별도 검증 대상이다.
- SORUA의 삭제 안내가 일반 ServiceInfoPage로 열렸다. sorua.ai.kr/account-deletion 전용 경로로 변경했다. 국내 맥미니 AI와 OpenAI의 차이는 기존 고지를 유지했다.
- 가톨릭 기본 기록과 별도 회원 서버 기록은 같은 저장소가 아니다. 오프라인 동작과 명시 동의를 보존하면서 공통 범위를 표시했다. 서버 전체 삭제는 현재 회원만 트랜잭션으로 처리하고 삭제 원장을 갱신하여 과거 백업과 커서를 무효화한다. 배포 런타임의 afterMutation 백업 파기 경로도 포함했다.
- 가톨릭 서버 개별 삭제에 취소 가능한 확인을 추가했다. 확인창에는 처리중 표시를 띄우지 않으며, 중복 확인·오래된 세대·백그라운드 콜백을 막는다.
- 회원탈퇴 성공 후 연결 FlowSession의 로컬 세션도 정리하도록 연결했다. 서버 미확인이나 재인증 실패는 정리를 시작하지 않는다.
- 네 웹의 별도 삭제 페이지에는 앱명, 기기/서버/탈퇴의 차이, 앱 재설치 없는 이메일 요청, 본인 확인, 완료 확인, 보관 상세 안내와 사본 범위를 표시했다. 이메일 링크는 접수·삭제 완료를 의미하지 않는다.

## 공통화에서 유지한 사실 차이

- MAEON의 기본 기록은 여전히 메모리다. 민감한 묵상 원문을 사용자의 새 동의 없이 디스크 저장으로 바꾸지 않았다. 서버 저장은 실제 활성 빌드에서 별도 동의·저장하는 경로다.
- 계정·로그인 제공자·AI 제공자·내용·보유기간은 앱별 실제 계약이다. 공통 기능명 때문에 제공자나 정책을 거짓으로 동일하게 쓰지 않았다.
- 현재 후보 코드·테스트와 이미 배포한 앱/웹·스토어 양식을 구분한다. 이번 작업에서 운영 DB 파기·서버 재시작·스토어 제출·실회원 탈퇴를 실행하지 않았다.

## 확인이 남은 출시 증거

- 네 실제 HTTPS 삭제 URL과 개인정보 페이지를 배포 후보와 대사.
- 각 앱의 실제 소셜 로그인·탈퇴·Apple 토큰 해제와 서버→기기→백업 정리 실증. 테스트 계정만 사용.
- 실제 배포 스케줄러, 로그·백업·외부 처리자별 보유·파기와 복원 방지 실증. 모의 retention_plan을 운영 정리로 보지 않는다.
- Apple App Privacy / Google Data safety / 최종 SDK 매니페스트 / 권한 설명을 각 제출 빌드에 맞춰 확정.
- 현재 배포 버전을 자동 교체하거나 기존 심사 대기 빌드를 재제출하지 않는다.

테스트·분석·빌드의 실제 결과는 data-rights-verification-20261101.json과 후속 기록을 따른다. 미검증 항목을 완료로 표시하지 않는다.

## 추가 언어 색상 제안 (디자인 검토, 코드 미적용)

사용자 제안: 한글·영문·한자를 색으로 구분. 검토 방향은 한글 짙은 먹색, 영문 청회색, 한자 짙은 갈색이며 원문·번역을 함께 보여주는 콘텐츠 영역에 우선 한정한다. 한국어/English/漢文 표기를 함께 사용하고 색만으로 정보를 구분하지 않는다. 밝은/어두운 화면과 글자 확대 가독성을 확인한 뒤 적용 범위를 결정한다. 이번 기록·삭제 변경이 색상 적용 완료를 의미하지 않는다.

## 빌드와 다음 등록 후보

이번 Android 산출물은 TEST 표시의 Debug 검증본이며 설치·스토어 업로드하지 않았다. 기존 applicationId·서명키·소스 버전은 바꾸지 않았다. 다음 등록 후보의 빌드 번호는 각 스토어의 현재 최고 번호와 대사한 뒤 앱별로 부여해야 하며, 이 Debug 검증본이나 기존 제출 번호를 그대로 새 심사 후보로 올리지 않는다. iOS 시뮬레이터 컴파일은 배포용 서명·실기기·아카이브 개인정보 보고서 검증을 대신하지 않는다.

## Web 네트워크 차단 검증의 범위

새 브라우저·빈 합성 로컬 저장소에서 외부 네트워크를 차단하고, 빌드에 포함된 CanvasKit을 로컬에서 공급하여 메뉴→기록 관리→취소→전체 로컬 삭제→PC 크기 전환을 검사했다. SORUA는 실제 빌드의 /app/ base 경로로 확인했다. 이 접근성/기능 검사를 실회원 서버 탈퇴나 운영 배포 검증으로 보지 않는다.

차단 환경에서 ONARIA/NAREUM/SORUA의 Web 엔진 대체 글꼴이 Google 리소스를 요청하는 점과 일부 캡처의 글자 미표시를 관찰했다. 이 세 앱의 완전 오프라인 Web 글꼴 가독성은 PASS로 표시하지 않는다. 웹 렌더러/대체 글꼴의 자체 제공 또는 접속 정보 처리 고지, 정상 네트워크/실기기 글꼴 표시를 다음 공개 후보에서 대사해야 한다. 이 브라우저 관찰을 iOS/Android SDK의 수집 여부 판정으로 그대로 복사하지 않는다. MAEON의 확인한 종료 후 홈 캡처는 번들 글꼴로 읽을 수 있었다.
