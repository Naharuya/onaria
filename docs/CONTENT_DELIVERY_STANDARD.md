# 콘텐츠 전달·캐시 공통 기준
확정일: 2026-10-31 KST. 사용자 요청: 기독교·불교·가톨릭·철학 모두 적용.

## 실행 기준
1. 기본 안내·고정 예시·검증된 기본 콘텐츠는 로컬에서 먼저 표시한다. 첫 화면과 위기 안내를 서버·AI·캐시 복원 완료에 종속시키지 않는다.
2. 반복 제공할 공개 콘텐츠는 이 앱이 소유한 독립 가비아 backend/콘텐츠 저장소에서 버전과 출처를 함께 제공한다. 실제 호스팅·HTTPS·배포가 검증되기 전 운영 적용으로 보고하지 않는다.
3. 서버 조회·백그라운드 갱신·로컬 캐시는 공개 콘텐츠 전용이다. 계정·대화·메모·감정 기록·토큰은 포함하지 않는다. 개인화 답변을 공용 콘텐츠로 저장하지 않는다.
4. 각 앱은 자체 API·DB·캐시 키·출처·종교/철학 분류를 소유한다. 다른 앱의 운영 API·자료·계정·키를 fallback으로 연결하지 않는다.
5. ETag/버전으로 중복 전송을 줄이고 겹친 요청을 합친다. 갱신은 짧은 timeout·재시도 간격을 둔다. redirect를 따라 인증정보나 요청을 다른 서버로 보내지 않는다.
6. 안정적인 배포용 기본 자료는 마지막 검증본으로 동작한다. 게시 승인·권리 철회가 가능한 자료는 표시 전에 서버 승인을 재확인하며, 실패 시 오래된 인용을 다시 노출하지 않는다.
7. 원문·번역·출처·저작권·검수/초안 표시는 저장·조회·카드·공유에서 유지한다. 캐시를 적용했다고 자료가 승인된 것은 아니다. 미승인 자료를 자동 수집·게시하지 않는다.
8. 활성 대화·선택한 질문·저장한 기록은 버전 스냅샷으로 고정한다. 갱신이 사용자가 읽고 선택한 내용을 중간에 바꾸지 않게 한다.
9. 이미지·음성·영상 추가 시 공개 여부·사용권·파일 크기·해시 버전·Content-Type을 확인한 전용 파일 경로와 캐시 정책을 사용한다. 사용자 파일은 공개 캐시에 넣지 않는다. CDN·미디어 이전은 실제 구현/검증 전 완료라고 하지 않는다.
10. AI는 개인화가 필요한 부분에 사용하며 반복 기본 콘텐츠를 매번 새로 생성하지 않는다. Safety는 모델/검색보다 먼저 처리하고 출처 없는 인용을 생성하지 않는다.
11. 최초 화면·콘텐츠 조회·서버 처리·AI 생성 시간을 따로 측정한다. 내부/외부 네트워크를 각각 검증하고, 실제 전후 측정 없이 지연 해결·성능 수치를 보장하지 않는다.

## 배포 수용 기준
- 로컬 즉시 표시, 느린/끊긴 네트워크, 잘못된 스키마·다른 앱 자료, 중복 요청, 304, 권리 철회, 앱/화면 종료를 검증한다.
- 공개 콘텐츠와 계정·관리자 응답의 캐시 정책을 구분한다.
- 서버·앱·웹 변경은 각각 테스트/빌드·TEST 채널·배포 대상을 확인한다.
- 로컬 코드/테스트, 실제 API/기기, 운영 배포를 나눠 기록한다.

## 이 프로젝트의 적용 상태
기독교 ONARIA: /v1/content/verses와 앱 로컬 우선 갱신·공개 자료 저장 및 AI Server-Timing을 앞선 작업에서 추가했다. 공개 원본은 backend/src/public_verses.json이며 앱 자산과 동기화한다. 개인 API는 no-store다. 이전 작업의 로컬 검증: backend 11, Flutter 8 PASS. 가비아 배포·기기 업데이트·실측은 미완료다.

운영 배포·실기기 반영·성능 실측은 이번 코드 작업과 별도로 확인한다. 공통 기준 도입은 다른 앱 데이터의 통합이나 출시 승인 완료를 뜻하지 않는다.
