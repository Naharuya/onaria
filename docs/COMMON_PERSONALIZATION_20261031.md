# 공통 맞춤대화 계약 · 2026-10-31

사용자 지시로 ONARIA·불교(NAREUM)·가톨릭(maeon)·SORUA의 맞춤대화 기준을 통일했다. 코드 적용과 운영 배포는 별개다.

## 다섯 가지 입력

| 기준 | 반영 |
|---|---|
| 감정 | 선택 감정 또는 직접 입력한 마음을 유지한다. 긍정·부정·복합 감정을 단정하지 않는다. |
| 강도 | 1–10 자기보고 값. 어려운 감정의 7 이상에서는 짧은 답변과 쉬는 선택을 안내한다. |
| 상황 | 감정 구분만 답한 문장을 상황으로 단정하지 않고, 처음 설명한 상황과 명시적 정정(사실은·정정·그게 아니라)을 우선한다. |
| 원하는 도움 | 쉼·이해/연결·정리/조언·좋은 마음 누리기를 보수적 규칙으로 구분한다. 부정한 선택을 요청으로 처리하지 않는다. 최근 명시한 선택이 우선한다. |
| 이미 답한 내용 | 현재 세션 최대 5답변과 실제 질문 이력을 참조한다. 동일 질문과 이미 답한 도움 질문을 피한다. 모르겠다는 답을 강제로 같은 질문으로 반복하지 않는다. |

공통 핵심은 lib/care_personalization.dart다. 세 서버의 독립 복사본은 backend/src/care_personalization.js다. 앱끼리 런타임 import·계정·DB·서버·키를 공유하지 않는다. 키워드 기반 로컬 분기이며 자유문장의 모든 의미를 이해하는 AI라고 표시하지 않는다.

## 앱별 관점과 경계

| 앱 | 적용 관점 | 유지한 경계 |
|---|---|---|
| ONARIA | 기독교의 사랑·돌봄, 선택적 말씀 | 기존 안전·동의·검증된 성경 자산 |
| 불교 | 알아차림·자비 | 미승인 경전/검수 제한과 강도별 정책 |
| 가톨릭 | 사랑·자비, 선택적 묵상 | 외부 AI·계정·서버 전송 비활성, 세션 메모리 처리 |
| SORUA | 사실·해석·가치·선택의 다양한 관점 | 기본 기기 내 성찰, 서버·회원·동의 설정 유지 |

관점 문장은 앱 자체 성찰이며 경전·철학자의 직접 인용으로 표시하지 않는다. 콘텐츠 출처·권리·검수 게이트를 우회하지 않는다. 위기 입력은 개인화 처리와 외부 모델보다 먼저 차단한다. 서버는 새 컨텍스트의 감정·상황·답변·질문도 위기 검사한다.

## 예시 보존과 공통 제공

- 세 앱의 기존 상황 예시 96개, 불교 강도별 예시 64개, 가톨릭 기본 상황 예시 5개를 원문 그대로 합쳤다. 감정별 15개(감정별 목록 합계 240개, 공통 문장 중복 포함)다.
- 가톨릭의 기존 구어형 카드명(예: 기뻐요)은 같은 기본 감정 목록으로 연결한다. 평온·기타·직접 입력 감정에는 기존 공통 상황 예시 5개와 공통 대화 목록을 제공한다.
- 기존 질문별 대화 예시 142개와 감정명 치환 문장 2종도 공통 목록에 보존했다.
- 같은 문장은 각 목록에 한 번 표시하고 출처별 기록은 보존한다. 원문·소스 위치·변경 전 SHA-256은 personalization-example-inventory.json에 기록했다.
- 세 앱은 상단 목록 아이콘, 가톨릭은 대화의 ‘감정 예시 모두 보기’에서 해당 감정 상황 예시와 펼쳐 보는 공통 대화 예시 전체를 선택할 수 있다. 기본 미리보기의 2/5개 제한은 전체 목록 삭제를 뜻하지 않는다.
- 기존 질문별 예시 선택·검사 함수와 원문 목록을 보존했다. 질문과 무관한 모든 예시를 기본 미리보기에 강제로 넣지 않는다.
- 사용자 대화에서 예시를 자동 수집하거나 추가 저장하지 않는다.

## 데이터 흐름과 호환성

새 Flutter 요청은 기존 session 내부에 선택적 personalizationContext(version 1)를 담는다. 기기 내 맥락은 감정·강도·상황·도움 분류와 현재 세션 최대 5답변(각 2,000자)·질문 이력이다. 기존 외부 AI 동의가 먼저 적용된다. 새 계정/영구 저장/로그/분석 수집은 추가하지 않았다. 가톨릭은 요청 클라이언트를 추가하지 않았다.

서버 전송을 사용하는 세 앱의 크기 제어 구현은 lib/care_request_budget.dart다. 세 서버의 기존 JSON 한도 16KiB를 유지한다. 실제 클라이언트 전송은 UTF-8 JSON 15,000바이트 이내로 맞춘다. 현재 입력은 그대로 보내고, 지난 답변·상황·기존 요약/질문은 최대 256자부터 앞뒤를 남기는 방식으로 필요 시 더 줄인다. 마지막 답변은 별도 userMessage를 서버에서 복원하여 중복 전송하지 않는다(historyCompacted). 로컬 원문과 감정카드 예시 은행은 수정하지 않는다. 메타데이터만으로 한도가 부족하면 승인된 콘텐츠 ID/후보 목록을 부분집합으로 줄이며 새 인용을 만들지 않는다.

압축한 맥락에서는 기기에서 전체 답변으로 분류한 원하는 도움을 현재 세션의 자기보고로 전달하고, 서버가 현재 입력의 명시적 변경·거절을 다시 반영한다. AI에는 답변별 최대 512자, 상황 512자, 질문별 200자로 제한한 맥락을 제공한다. 전송 시 생략된 중간 내용은 서버/AI가 보지 못할 수 있다. 기기에서는 자르기 전 원문을 위기 검사하고, 서버에서는 전체 수신 값과 복원한 현재 답변을 검사한 후에만 모델을 사용할 수 있다. 기존 개인정보처리/보유기간/동의·삭제 게이트는 유지한다.

이전 클라이언트는 새 필드 없이도 동작한다. 이전 서버의 session passthrough와 호환되지만 개선된 서버 로컬 분기·프롬프트가 운영에 반영되려면 해당 앱 전용 서버 배포가 필요하다. 배포·설치·스토어 제출은 이번 작업에 포함하지 않았다.

## 검증과 적용 상태

이번 변경의 검증 결과와 미실행 항목은 PERSONALIZATION_IMPLEMENTATION_20261031.json을 따른다. 이전 공통 기본동선 보고서의 빌드/시험 결과를 이번 변경 결과로 간주하지 않는다.
