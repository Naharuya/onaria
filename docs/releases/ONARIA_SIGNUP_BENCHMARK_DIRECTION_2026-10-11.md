## 새 방향
쉽게 시작하고, 한 회원의 기록을 안전하게 이어가며, 복구와 탈퇴를 끝까지 처리한다.

1. 첫 화면: 로그인/회원가입 통합 시작, 마지막 성공 로그인 방식 표시(현재 선택 가능한 상태 확인). 네이버·카카오·Google·Apple 기존 지원 보존. 모든 제공자에서 동일한 후속 흐름.
2. 신규가입: 소셜 인증 → 기존 연결 조회 → 신규인 경우 필수 약관/연령확인 → 시작. 이름·전화번호·교회 입력은 초기 가입 화면에서 제거하고 필요한 기능 시점으로 이동. 표시명은 자동 별칭+나중 변경. 기존 데이터 삭제 없음. 연령은 현재 만18세 이상 정책 유지; 체크를 실제 연령 인증이라고 표현하지 않음.
3. 미연결 소셜: 신규 계정임을 명확히 알리고 기존 이용자에게 기존 계정으로 연결할 경로 제공. 기존회원인지 새회원인지 먼저 사용자에게 추측하게 하지 않음. 다른 제공자의 동일인을 서버가 자동으로 안다고 가정하지 않음.
4. 내부 memberId: 제공자+검증된 고유ID는 로그인 수단. 회원·기록·동의는 내부 memberId 기준. 기존 구현의 memberId/identity mapping을 재사용하고 세션/기기 기록의 경계를 검토. 무조건 재작성하지 않음.
5. 연결: 로그인된 기존 계정 소유 증명과 새 소셜 인증을 모두 요구. 동일 이메일·이름·전화 입력만으로 자동 병합하지 않음. 이미 다른 memberId에 속한 ID는 자동 이동하지 않음.
6. 기록: 회원별 저장/표시 분리. 기기 공용 기존 기록은 자동 귀속하지 않고 기기기록으로 보존 후 명시적 가져오기. 계정 전환 시 이전 회원 기록 차단.
7. 복구: 기존 로그인 방식 안내 → 이미 연결한 다른 제공자 → 검증된 복구수단. 이메일 일회용 링크는 서버 이메일 검증/발송 기반을 확인한 후 후보로 설계. 전화번호 입력만으로 복구 금지. 새 외부 인증 서비스 계약이나 유료 발송을 시작하지 않음.
8. 로그아웃: 회원 로그아웃과 제공자 연동해제 분리. 회원 기록 보존은 해당 회원 범위에서만 접근; 다른 계정에 보이지 않음. 오프라인 처리와 서버 폐기 재시도 정책 명시.
9. 탈퇴: 직전 본인 재확인 → 서버/기기/백업 대상 안내 → 확인 → 삭제/연동철회/세션폐기 → 완료. 응답유실/부분실패는 처리중 또는 확인필요로 표시. 기본 방향은 계정소속 개인정보와 기록 삭제, 사용자 요청 내보내기 후 삭제. 기존 데이터는 설계/구현/검증 완료 전 삭제하지 않음. 보존예외는 실제 목적/구현/고지 확인 후 결정.
