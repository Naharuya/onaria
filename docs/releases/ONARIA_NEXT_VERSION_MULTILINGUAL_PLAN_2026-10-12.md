# ONARIA 다음 버전 개발 기록 — 다국어 확장 준비

작성일: 2026-10-12
적용 시점: Build 20 이후 다음 버전 개발

2026-10-24 범위 정리: 가톨릭은 별도 앱으로 유지한다는 사용자 결정을 따른다. 이 문서의 다국어 구조 준비는 유지하되, 아래 “향후 종교 선택 구조”는 당시 제안이며 Christian ONARIA 내부 개신교·가톨릭 선택 구현을 승인하는 요구사항이 아니다. 언어별 신앙 자료는 각 앱의 전통·라이선스·데이터 경계를 유지한다.

## 결정 사항

ONARIA는 다음 버전부터 다국어 확장을 고려한 구조로 정리한다.

초기 권장 순서:
1. 한국어 완성 및 안정화
2. 앱 전체 i18n 구조화
3. 영어 베타
4. 영어 마음대화·안전·신앙 콘텐츠 검수
5. 일본어 추가
6. 국가별 약관·개인정보·스토어 현지화
7. 중국어·스페인어 등 추가 확장 검토

## 단순 번역으로 처리하면 안 되는 영역

다음 항목은 일반 UI 번역과 분리해 현지화가 필요하다.

- 마음대화 표현과 감정 뉘앙스
- 감정명 및 성찰 질문
- 신앙 표현과 성경 콘텐츠
- 위기·자해·정신건강 관련 안전문구
- 국가별 긴급 연락 안내
- 이용약관·개인정보처리방침·동의문
- App Store / Play Store 설명과 스크린샷
- 고객지원 및 이메일/알림 문구

## 예상 문제

### 1. 감정·대화 뉘앙스
한국어의 마음 표현을 직역하면 영어·일본어·중국어에서 어색하거나 의미가 달라질 수 있다.
언어별 자연스러운 대화 문체와 감정 표현을 별도로 설계한다.

### 2. 신앙 콘텐츠
언어마다 성경 번역본과 저작권 조건이 다를 수 있다.
언어별 허용된 성경 소스, 출처, 라이선스를 분리 관리한다.
개신교·가톨릭 콘텐츠 차이도 향후 종교 선택 구조와 함께 검토한다.

### 3. AI 안전 대응
한국어 위기 키워드만으로는 충분하지 않다.
언어별 위험 표현, 고정 안전 응답, 지역별 긴급지원 정보를 따로 검증한다.

### 4. 법률·개인정보
해외 서비스 시 지역별 개인정보·소비자·아동 관련 규정과 해외 데이터 이전 고지가 달라질 수 있다.
법률 문서는 단순 번역하지 않고 국가별 현지화 검토를 거친다.

### 5. UI/UX
문장 길이, 줄바꿈, 글꼴, RTL 언어에 따라 화면이 깨질 수 있다.
버튼·카드·설정·대화·알림 화면을 언어별로 QA한다.

### 6. 운영비 증가
언어 추가 시 번역, QA, 고객지원, 콘텐츠, 프롬프트, 스토어 자료 관리 비용이 증가한다.
지원 언어를 한 번에 많이 늘리지 않는다.

## 개발 요구사항

다음 버전에서 우선 구조만 준비한다.

- Flutter 화면 문자열 하드코딩 제거
- locale 기반 리소스 구조 도입
- 화면 문구, 감정명, 질문, 알림, 오류 메시지 분리
- 서버 응답 code와 표시 문구 분리
- AI prompt를 locale별 템플릿으로 분리
- 성경/신앙 콘텐츠 source + locale + denomination 메타데이터 구조 검토
- crisis/safety rule을 locale별로 분리
- 언어 설정 화면 추가 또는 OS locale 연동 설계
- 미지원 locale은 한국어 또는 영어로 안전 fallback
- 관리자 페이지에서도 언어별 콘텐츠 상태 확인 가능하도록 설계

## 개발 우선순위

다국어 때문에 현재 출시 안정화를 늦추지 않는다.

우선순위:
1. Build 20 / 현재 로그인·계정 구조 안정화
2. 한국어 출시 품질 확보
3. 다음 버전에서 i18n 기반 구조 반영
4. 영어 베타
5. 일본어
6. 추가 언어 확장

## 완료 기준

- 앱 UI 문자열 하드코딩 최소화
- locale 변경 시 주요 화면 정상 렌더링
- overflow / 잘림 없음
- AI prompt locale 분리
- safety locale 분리
- 성경 콘텐츠 라이선스 언어별 확인
- 개인정보/약관 현지화 필요 영역 명확히 분리
- 영어/일본어 추가 시 핵심 코드 재작성 없이 리소스 중심으로 확장 가능
