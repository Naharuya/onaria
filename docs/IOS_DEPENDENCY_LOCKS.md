# iOS dependency lock policy

Build ONARIA with `flutter build ios` or the `ios/Runner.xcworkspace` workspace.
The installed Flutter build tooling selects the workspace when available. The
project's Swift package reference points to Flutter's generated plugin package;
its dependencies are resolved by Xcode during the build.

Track these application dependency locks:

- `ios/Podfile.lock`: CocoaPods dependency versions/checksums for the tracked Podfile.
- `ios/Runner.xcworkspace/xcshareddata/swiftpm/Package.resolved`: the canonical
  workspace's Swift package resolution. It currently pins CwlCatchException 2.2.1.

Keep `ios/Runner.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved`
local and ignored. It was generated by the project-only workspace and matched
the canonical workspace lock byte-for-byte when this policy was established.
Do not delete it automatically or use it as a second source of dependency versions.

Build outputs, Pods, `.symlinks`, and `Flutter/ephemeral` remain generated and
ignored. Preserve original manifests, signing configuration and credentials.
Dependency upgrades should review lock diffs together with their manifest or
toolchain changes and verify the canonical workspace with an unsigned simulator
build. This policy does not change any app identifier, signing setting or server.
