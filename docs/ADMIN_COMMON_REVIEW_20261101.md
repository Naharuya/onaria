# 관리자 공통 구조 변경·검증 (2026-11-01)

## 결과

ONARIA / NAREUM / MAEON / SORUA에 동일한 관리자 업무 계약과 공통 UI 모듈을 자체 소유 코드로 반영했다.
기본 관리 구조는 공통 계층, 종교·철학별 검수 항목은 REVIEW_PROFILES로 분리했다. 계정·데이터·키·운영 서버는 합치지 않았다.
상세 계약과 실제 연결 범위: [ADMIN_COMMON_STANDARD.md](ADMIN_COMMON_STANDARD.md).

- 공통 역할 7개, 서버측 권한 검사, 개별 관리자 계정 관리 또는 기존 provider 회원 역할 관리.
- 최소 회원 집계, 버전 충돌 검사와 독립 승인을 갖춘 삭제·철회 접수 큐, 문의 배정/처리/재개.
- 트랜잭션 기반 공통 감사 기록과 연결 검증, 변조 감지 시 변경 차단.
- 백업/복구/삭제 후 복구 차단을 별도 상태로 표시하는 읽기 전용 확인 API.
- 공통 4항목+각 앱별 3항목으로 고정한 콘텐츠 버전별 독립 검수 기록.
- /admin/common 작업 공간(세 Express 앱), 기존 MAEON 관리자 콘솔의 공통 관리 섹션.
- 로그인·CSRF·권한 변경 반영·기존 비활성 Gate 보존. 운영 데이터나 외부 계정에 접근하지 않았다.

## 완료 범위와 남은 연결

이 변경은 개발 코드 구조와 로컬 합성 검증이다. 기본 서버에 실제 삭제 완료 확인기나 운영 백업 증거 어댑터를 임의 연결하지 않았다.
따라서 공통 요청의 최종 완료 확인은 기본적으로 차단되며 백업/복구는 미확인이다. 기존 앱 내 본인확인·탈퇴 집행 경로는 계속 사용한다.
문의 큐는 내부 참조 관리이며 외부 이메일 수집/전송을 하지 않는다. 원문은 기존 보호된 접수 경로에서 확인한다.
공통 검수 기록은 기존 콘텐츠 게시 파이프라인에 대한 자동 승인/일괄 이관이 아니다. 기존 출처·사용권·교리/전문검수·게시 제한은 계속 적용한다.
새 운영 메타데이터의 보유/복구 정책, 운영 신원/완료 증거/백업 어댑터 연결, 실제 서비스 검증은 운영 적용 전 남은 항목이다.
MAEON 역할 스키마 확장 코드는 로컬 합성 저장소에서 검증했으며 운영 DB 마이그레이션·관리자 활성화는 실행하지 않았다.

## 초기 실패와 수정

첫 네 저장소 동시 전체 실행에서 ONARIA 시작 5초 및 MAEON worker 시작 3초 제한을 넘긴 실패가 있었다.
제한값을 늘리거나 검사를 제거하지 않고 실행 동시성을 줄여 최종 전체 회귀를 통과했다.
초기 공통 UI 브라우저에서 이전 화면 폼을 새 화면 로딩 중 조작할 수 있고 새 버튼이 일찍 활성화되는 문제가 있었다.
이전 패널 즉시 제거와 새 컨트롤 잠금으로 수정한 뒤 네 앱 전체 브라우저를 다시 통과했다. 최초 실패 로그도 보존했다.
